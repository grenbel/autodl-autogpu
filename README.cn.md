# autodl-gpu

[English](README.md)

让 Claude Code 里的 AI 自己开关 AutoDL 的容器实例，有卡和无卡两种模式都行，并且让不用的机器及时关掉。

AutoDL 按量计费的实例从开机到关机按秒收费，和用不用 GPU 无关。训练跑完忘了关，或者 AI 的会话中途断了，钱都照扣。这个 skill 做三件事。

- **AI 主控开关机。** 有卡开机、无卡开机、关机、切换模式、读状态与余额，都由当时对话里的 AI 完成，不用人去点
- **守护程序兜底。** 实例上有一个守护脚本，按 GPU、CPU、磁盘、网络的实际占用判断空闲，空闲满你定的时长就关机。AI 的会话断了它照样关
- **预算关口。** 你说过的模式用法与预算记在本机，每次开机前先过一遍，快用完时先问你

它只提供方法。什么时候开、开哪种模式、什么时候关，由 AI 按任务和你的习惯决定。这三样都不是绝对的保证，各管什么、管不了什么见"哪一样才是硬上限"。另有一个默认关闭的功能，实例所在的主机一直没有空闲卡时，克隆一台同样配置的实例接着跑，见"没有空闲卡时自动克隆"。

## 需要什么

| 依赖 | 说明 |
|---|---|
| Claude Code | 命令行、桌面 App、IDE 插件都可以 |
| Python | 3.8 及以上，各分支要较新的补丁版本，即 3.8.17、3.9.17、3.10.12、3.11.4、3.12 起。版本不够时 AI 的环境检查会指出来 |
| OpenSSH 客户端 | `ssh` 在 PATH 里 |
| bash | Windows 上是 Git Bash，也就是 Claude Code 的 Bash 工具 |

| AutoDL | 一个账号，一台按量计费的普通容器实例 |

没有浏览器工具也能用，见"两种档位"。

## 安装

```bash
git clone https://github.com/grenbel/autodl-gpu ~/.claude/skills/autodl-gpu
```

也可以把这条命令发给 AI，让它来装。装好后新开一个对话就能用，第一次用时 AI 会自己检查本机环境，缺什么会告诉你。

## 第一次使用

你要做的只有三件事。生成密钥、写 SSH 配置、检查环境、部署守护，都由 AI 照 `SKILL.md` 自己做。

1. **把公钥加进 AutoDL。** AI 会在对话里给你一行公钥，把它贴到 AutoDL 控制台实例列表上方的"设置SSH免密登录"里。每台电脑只做一次，对账号下所有实例生效。已经有加好的密钥，告诉 AI 用哪一把就行
2. **把登录指令发给 AI。** 在控制台复制这台实例的"登录指令"发给它，里面有主机和端口。密码不用给
3. **在 Claude 用的浏览器里登录 AutoDL。** 登录由你本人完成，AI 不碰密码与验证码

然后告诉 AI 这个项目要用哪台实例。每个项目第一次用时，它会问清五样东西。

- 实例，用哪一台
- 模式用法，三选一：无卡传数据、有卡跑实验配合着用，只用有卡，只用无卡
- 预算，有没有，多少，按金额还是按 GPU 小时，按月还是不分周期
- 守护设置，空闲多久自动关机（建议 15 分钟），要不要最晚关机，要不要控制台定时关机
- 没有空闲卡时要不要自动克隆，默认关闭，你不说就不开，见"没有空闲卡时自动克隆"

实例信息与守护设置由 AI 写进项目 CLAUDE.md 的 `## AutoDL` 段，模式用法、预算与克隆的设置记在本机。以后的对话直接用，不再问。

你给的模式用法与预算就是授权，AI 会在这个范围里自己开机花钱。它不设有效期，按实例记在这台电脑上，哪个项目的对话都能用。想看、想改、想收回，跟 AI 说一声就行。

## 怎么用

直接说要做的事，例如"把训练跑起来""数据传完就关机""这个月还剩多少预算"。AI 会按 `SKILL.md` 自己开机、部署守护、跑任务、关机，过程中不逐步打扰你，只在开机后和关机后各汇报一句。开机关机都不用你自己去控制台点（没有浏览器工具时除外，见"两种档位"）。

- **和自动科研、自动跑实验的流程一起用。** 你说"按计划把实验跑完"，或者别的跑实验的 skill 走到要用这台实例的那一步，AI 会先用上这个 skill，开机、起任务、关机都经它。项目 `CLAUDE.md` 的 `## AutoDL` 段里写着这台实例用它，所以这个项目里的对话都知道
- **它没有自己用上这个 skill 时**，输入 `/autodl-gpu`，或者直接说"用 autodl-gpu"
- **AI 只在对话进行时才能动手。** 让它在后台等任务跑完，它就能一直管到取回结果、关机。对话没了（应用关了、断网），任务照常跑，由实例上的守护按空闲关机
- 第一次在一台实例上开机时，你可能在控制台看到一个定时关机出现又消失。那是守护装好之前 AI 设的临时兜底，属于正常

## 没有空闲卡时自动克隆

AutoDL 的实例绑在一台主机上。那台主机的卡被别人占满时，你的实例就开不了有卡模式。平时 AI 会等着，每隔几分钟看一次，一有空闲卡就开机，等不到就告诉你。

你也可以让它在等不到时克隆。这个功能默认关闭，你明确说开启才会用。开启之后，等满你定的时长（默认 30 分钟）还没有空闲卡，AI 就新租一台同原机器配置一样的实例（同一地区，型号、卡数、CPU、内存都相同，驱动相同或更新，单价不更高，原机器有付费扩容的数据盘就同样扩容），把系统盘与数据盘拷过去，任务换到新机器上接着跑。找不到这样又有空闲卡的主机时它不克隆，继续等并告诉你。整个过程不用你在场。开启就是你事先同意这笔花费，到时候它不再问，动手之前告诉你一句要租的是什么、多少钱。

开启之前要知道这几件事。

- **它花钱。** 新机器从创建起按量计费，过的是开机的同一道预算关口，两台机器共用一份预算。原机器有付费扩容的数据盘时，新机器同样扩容，之后两台每天各扣一笔扩容费，关着也扣，直到你释放其中一台
- **原机器由你自己释放。** AI 不点释放。换过去之后它会告诉你数据核对到了什么程度、原机器每天还在扣多少、平台哪天会自动释放它，要不要释放、什么时候释放由你在控制台决定
- **没人接手的新机器会自己关机。** 克隆之前 AI 在原机器的系统盘上放一张克隆票（`/etc/profile.d/autodl-gpu-clone-ticket.sh`，了结时从两台上都撤掉），新机器带着它启动。对话在中途断了、没人接手时，到了票上的时刻新机器自己关机，不会一直空跑
- **一次克隆了结之前，不要自己拿原机器克隆或保存镜像。** 那张票会跟着拷过去，把那一台也关掉。什么时候了结 AI 会告诉你
- **AI 会把原机器无卡开两次。** 一次在克隆前做准备，一次在了结时撤票，每次几分钟，你只允许有卡的用法时也一样
- 每个任务最多克隆几次由你定，默认 1 次

做法的细节在 `reference/clone.md`。这个功能在真实账号上完整做过一次，那一次数据盘很小，见"平台"。

## 守护会留在实例上

装了之后最该知道的一件事。AI 第一次部署时会在实例上留下两样东西：数据盘上的守护脚本（`/root/autodl-tmp/.autodl-guard/`）和系统盘上的开机钩子（`/etc/profile.d/autodl-gpu-guard.sh`）。此后每次开机守护都自己起来，用的是上一次的设置。

平时这对你没有影响。下面几种时候才需要留意。

- **你不经 AI、自己在控制台开机时**（比如只是进去看看文件）。守护照样会起来。开着的终端、Jupyter、screen 或 tmux 本身不算在用，很轻的活动它也看不出来，所以只是看看代码、不跑东西，过了空闲时长机器就会被关掉。想让它先别关，跟 AI 说要留多久。另外，开机之前先看一眼这一行有没有定时关机，有就取消或改掉，否则到点它会把机器关掉。AI 设的定时要它在场才会去取消，对话中途断掉时可能还留在那一行上（早就过了点的旧定时开机后会怎样没有实测过，同样先取消）
- **重置系统或更换镜像之后**，下次让 AI 开机时告诉它一声。系统盘换新了，钩子多半也没了（没有实测过），AI 知道了会先设一个临时的定时关机兜底
- **用这台实例保存镜像或克隆实例时**。守护不认实例，把上面两样都带走的话，它在那边也会随开机自启、按同样的设置关机
- **不想让它随开机自启时**，让 AI 把钩子卸掉。从下一次开机起生效，这一次已经在跑的守护照旧

## 哪一样才是硬上限

几样东西各管一段，都不是绝对的保证。

- **空闲关机**看的是实际占用。卡死却还占着 GPU 或 CPU 的进程一直算在用，读不到的信号也按在用算，这两种时候它不会关
- **最晚关机**（可选）到点后不切断还在用的任务，只是干完就关
- **预算**在开机前和要多开一段的时候把关，不是硬上限。任务自己跑过了计划的时长，没有人再查
- **控制台定时关机**（可选）到点由平台直接关机，会切断任务。它是唯一绝对的上限，要你选了才设
- **克隆票**只在克隆时有，只管克隆出来、还没人接手的新机器，到了票上的时刻就关机。它同守护的开机钩子走的是同一条路，AI 在克隆之前会先确认这条路此刻是通的，不通就不克隆

想要一个绝对的上限，就让 AI 每次开机都设控制台定时关机。

## 两种档位

| | 有浏览器工具 | 没有浏览器工具 |
|---|---|---|
| 开机 | 自动 | 你在控制台点，AI 告诉你点哪一行的哪个按钮、什么时候点。余额、提醒、这一行的定时关机也由你看了告诉它，要设或取消的定时由你来设 |
| 关机、守护、跑任务 | 自动 | 自动 |
| 关机后的核对与记账 | 自动 | 你看一眼这一行是不是已关机、还挂着的定时取消掉，再把收支明细里最后一笔扣费读给 AI。你不在的时候，记账要等你回来 |

自动开机靠的是浏览器工具"在页面里执行脚本"的功能。有的环境或模型不愿意用它来点按钮，这时按右边一档用。

## 它不做的事

- 不输入密码，不处理验证码，不保存令牌，不向你要密码或私钥内容
- 不点释放、重置系统、更换镜像、升降配置、迁移、转包月、充值、续费，不在费用与账单的页面里做任何操作。收支明细它只读，用来核对扣费。克隆只在你开启了自动克隆之后做，没开启时它不碰
- 控制台上只点固定的几种按钮：开机、无卡开机、定时关机的设置与取消；开启了自动克隆时另有克隆对话框与创建页上固定的几处，最后一下是"创建并开机"。页面和预期对不上时它停下告诉你，不猜也不绕过
- 强制关机会切断任务，只在你当场同意时用
- 不在控制台上关机。关机走 SSH；少见的情形下开机后 SSH 一直连不上，它会请你自己在控制台点关机。这时你可能看到关机确认框弹出又消失，那是它在读框里的原文

## 隐私

- 本机记录（授权、用量账本、克隆的设置与记录、校准）在 `~/.autodl-gpu`，不上传，不进任何仓库。环境变量 `AUTODL_GPU_HOME` 可以改它的位置
- 项目里的开关机记录在项目目录的 `.autodl/power_log.jsonl`；有一次没了结的克隆时，另有一份给人看的副本 `.autodl/clone_pending.json`
- 页面脚本只读控制台页面、点固定的几个按钮，不发网络请求，不读 cookie。为了刷新页面后不用把脚本重贴一遍，AI 会把脚本自己的文本放在控制台那个标签页的会话存储里（每份脚本一项，至多三项，关掉标签页就没了），取回时重新核对校验和才执行
- 克隆时为了连上新机器，脚本从页面自己的数据里读新实例这一行的 SSH 主机、端口与登录指令（三样互相核对），不读密码；读不到时 AI 会请你把登录指令贴给它。为了认出哪一行是新建的，克隆记录里存着创建之前列表里各实例 ID 的摘要，不存 ID 本身
- 收支明细那一页上有账号下所有实例的扣费行和余额，AI 读得到，用的只有这台实例的行。余额只用于当次核算，不保存。导入的扣费行（流水号、时刻、金额）存进本机记录，用来算预算和认出重复导入，不写进项目文件

2026-09-29 到 10-02 在一台真实的实例上分几次做过实机测试。10-02 的验收用的就是发布的这一版守护脚本、ctl 与页面脚本，走过的有：两种模式的开机，开机前设定时关机、之后取消，随开机自启，按空闲关机，最晚关机不切断任务，守护进程停掉之后的处理。其中一遍由一个只读过发布文件、没参与开发的 AI 独立做完。控制台定时到点把机器关掉，是 09-29 看到的。

实例一侧是 AutoDL 的普通容器实例，守护脚本需要 bash、flock 与 timeout。测试用的官方 PyTorch 镜像里都有；别的镜像缺了哪样，守护会直接报出来。

## 测试

只是使用的话不用跑测试。想自己验证或者要改代码时再跑。测试分三组，各有各的前提，三组都过才算全过。

| 测什么 | 怎么跑 | 需要 |
|---|---|---|
| 本机一侧：ctl、本机记录与账本、文件传输、文档与页面脚本的静态检查 | `python -m pytest tests -q` | Python 与 pytest。其中一部分还要 bash 或 WSL，缺了会跳过，加 `-rs` 看跳过了哪些 |
| 实例上的守护脚本 | `bash tests/test_guard.sh` | Linux 的 bash，Windows 上用 `wsl.exe -e bash tests/test_guard.sh` |
| 控制台的页面脚本，实例列表页的与克隆创建页的（离线，用页面样本） | `python tests/console/run_headless.py` | 本机装有 Edge 或 Chrome（用它的无界面模式，不联网）。没有的话在浏览器里打开 `tests/console/run.html`，做法见该文件开头；这一页只测实例列表页的那份脚本 |

pytest 跑完会提醒还有后两组。守护脚本的测试用桩程序代替 screen、tmux、nvidia-smi 与关机命令，不会真的关机。但它用 `pkill -f` 按命令行里的字样（例如 `sleep 600`）结束测试进程，那台 Linux 上命令行里带这些字样的别的进程也会被结束。所以不要同时跑两份，不要在跑着正事的机器上跑，更不要在实例上跑。没有持续集成，公开仓库里的测试结果以你自己跑出来的为准。
